# Mini Play — library expansion, interface upgrade, bug fixes

**Date:** 2026-08-11
**Status:** Implemented

## Goal

Add more games, upgrade the hub interface, and fix bugs in `index.html`.

## Constraints

- The hub is a static site (`austin-code.com`), no build step, no server.
- Games run in an `<iframe>` from the same origin, so every game must be fully
  self-contained. Any CDN dependency is a breakage waiting to happen and any
  `http://` dependency is blocked as mixed content on the HTTPS site.
- `index.html` keeps its current structure: hand-written cards plus a JS
  registry. Splitting the file or generating cards was explicitly out of scope.

### Vendoring rules applied

Upstream copies were modified only where they would otherwise break or leak:

- **Removed** the Google AdSense loader and Google Analytics beacons from
  Hextris; removed the Google Analytics beacon from HexGL.
- **Vendored** Sudoku's jQuery 3.6.0, Bootstrap 5.1.3 and SweetAlert into
  `Games/sudoku/vendor/js/`, plus Font Awesome 5.15.4 CSS and webfonts into
  `Games/sudoku/vendor/fontawesome/`. Font Awesome is load-bearing — it draws
  the hint, pause and next-step controls, not just decoration.
- **Stripped** the `integrity`/`crossorigin` attributes from those now-local
  script tags. Left in place, Subresource Integrity would have refused to
  execute the local files and the game would have failed silently. Also
  collapsed three duplicate Bootstrap loads down to one.
- **Vendored** the Google Fonts used by Hextris (Exo 2) and Tower Platformer
  (Cherry Swash) into each game's `vendor/` directory.
- **Removed** the `buttons.github.io` social widget from Sudoku rather than
  vendoring a third-party tracker.
- **Repointed** HexGL's favicon from `http://hexgl.bkcore.com/` to its local copy.

### Entry points

`Games/racer/index.html` is a table of contents, not the game. The registry
points at `Games/racer/v4.final.html`. Every other game entry is `index.html`.

### Previews

Preview thumbnails were generated by rendering each game headlessly and cropping
the result (`Games/<name>/<name>-preview.png`, 720px wide). Astray is the
exception: it is WebGL and renders black without a GPU, so it uses hand-written
CSS maze art (`.astray-art`).

## 2. Interface

Keeps the lime-on-navy identity. Added:

- **Light/dark theme toggle** in the sidebar, persisted, defaulting to the
  system preference. All chrome colors moved onto tokens; a
  `:root[data-theme="light"]` block overrides them. Card preview art stays dark
  in both themes by design — it is illustrative, not chrome.
- **Sort control**: Featured (DOM order), New first, A–Z, Recently played,
  Most played. Implemented with the CSS `order` property so no DOM reshuffling
  is needed. "New first" relies on `Array#sort` being stable, so non-new cards
  keep their featured order.
- **NEW badges** in the top-right corner of the ten newly added game cards.
  Both the badge and the "New first" sort read the same `isNew` flag on the
  registry entry, so they cannot disagree about which games are new.
- **Play-count badges** on cards, from the new per-item stats.
- **Unified search** across Games, Apps and Favorites. Previously the search box
  only filtered Games and was hidden elsewhere.
- **Favorites for apps.** App cards had no `data-game-id`, so their star did
  nothing. They now have ids (101–103) and working favorite buttons.
- **Keyboard**: `/` focuses search, `Escape` closes the player or beta modal,
  arrow keys move between visible cards, visible focus rings throughout.
- **Loading spinner** on the player stage while an iframe loads.
- **Responsive**: the theme toggle collapses to an icon under 900px.
- `aria-live` on the result count, `aria-pressed` on favorite and theme buttons.

## 3. Bugs fixed

| # | Bug | Fix |
|---|---|---|
| 1 | `POLL_MS = 15e45` — `setInterval` coerces via ToInt32, so the webhook polled in a tight loop instead of every few hours | Whole webhook block removed |
| 2 | Webhook rendered remote-controlled modals whose buttons called `window.open(btn.url)` on an unvalidated URL, from a public `webhook.site` endpoint anyone could post to | Removed |
| 3 | `launch()` assigned `currentGame = id` before validating the id existed | Validate first, assign after |
| 4 | Favorited beta games appeared in Favorites in normal mode | Beta filter now applies to Favorites too |
| 5 | Apps could not be favorited | Apps given ids and favorite buttons |
| 6 | Favorites count always said "games" even for apps | Counts "items" in Favorites |
| 7 | Favorites/cookies lost on `file://` and capped at 4KB | Migrated to `localStorage` with a one-time cookie import |
| 8 | Playtime round-tripped through a lossy `days,hours,minutes` cookie | Stores raw minutes |
| 9 | Tower-card canvas ran `requestAnimationFrame` forever, even when the card was filtered out or the tab was hidden | `IntersectionObserver` + `visibilitychange` start/stop |
| 10 | Same canvas set `width`/`height` to 0 when its card was hidden | Keeps last good size |
| 11 | Reload button re-assigned an identical `src`, a no-op in some browsers | Bounces via `about:blank` |
| 12 | `updateView()` re-scanned the whole registry per card on every keystroke | Prebuilt `keyById` map |
| 13 | Beta modal tracked pending state through `currentGame`, which cancel then nulled | Dedicated `pendingBetaId` |
| 14 | `#beta` in the URL did not restore beta mode on reload | `openFromHash()` handles it |
| 15 | No `hashchange` handling; deep-link hash persisted after closing a game | `hashchange` listener; hash cleared on close |
| 16 | Debug panel text was hardcoded `#d7e2f1`, invisible in light theme | Uses `var(--text)` |
| 17 | Hardcoded view count of "30 games" in markup | Corrected, and JS owns it |

## 4. Known risk

Cards remain hand-written while the registry is data, so the two can drift —
and ten new games means ten more places for that to happen. Mitigation: the
debug engine (`#debug`, or type `debug123`) now has an **Integrity** section
that reports cards with no registry entry, registry entries with no card,
duplicate cards, mismatched ids, and missing `data-game-id`. It is a detector,
not a cure; generating cards from the registry would be the real fix.

- All ten games rendered in headless Firefox and visually confirmed playable.
- All 45 registry `src` paths and 22 preview images confirmed to exist.
- All 45 card `data-id`s confirmed to match registry keys.
- Both inline scripts pass `node --check`.
- Hub rendered in light and dark themes; debug Integrity check reports OK.
- Deep-link launch verified for `#tetris`, `#chess`, `#game2048`.

Not verified: Astray and HexGL gameplay beyond first paint — both need a GPU
